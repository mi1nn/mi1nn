## 개요

음성 명령으로 재난 구조키트를 구성하는 두산 M0609 협동로봇입니다. "키트1번" 같은 음성 명령이 웨이크워드 감지, Whisper STT, GPT-4o를 거쳐 검증된 작업이 됩니다. 로봇은 RGB-D 카메라로 품목을 찾고, MoveIt 2로 충돌 없는 경로를 계획해 키트에 담습니다.

## 담당

**시스템·ROS 2 인터페이스 설계, 음성 패키지(`kit_voice`), 비전 패키지(`kit_vision`)와 초기 위치 추정, OctoMap 장애물 환경, 전체 시스템 통합**

## 한 일

### 1. 시스템·ROS 2 인터페이스 설계
- **인터페이스 계약 먼저 정의.** 음성, 비전, 컨트롤러, 모션, DB 사이의 토픽·서비스·메시지를 공용 `kit_interfaces` 패키지로 정리해, 각 패키지가 다른 패키지의 코드가 아니라 계약에만 의존하도록 설계했습니다.
- **병렬 개발.** 계약을 초반에 확정하고 가짜 검출 결과를 발행하는 mock 노드를 두어, 모델과 로봇이 준비되기 전에도 좌표 파이프라인을 먼저 연결할 수 있게 했습니다.

### 2. `kit_voice` — 음성 명령을 검증된 작업으로
- **웨이크워드.** openWakeWord로 "hello rokey"를 감지하고, 마이크를 80 ms 단위로 읽습니다. STT를 시작하기 전에 마이크를 놓아 STT가 같은 장치를 열 수 있게 했고, USB 마이크가 빠지거나 늦게 연결되면 자동으로 다시 엽니다.
- **음성 인식(STT).** 16 kHz로 5초 녹음해 Whisper API로 보냅니다. 16 kHz 입력 장치를 자동으로 고르고, 다른 환경을 위해 직접 지정할 수도 있게 했습니다.
- **명령 해석과 검증.** GPT-4o(LangChain)로 문장을 키트 이름·품목·수량 JSON으로 바꿉니다. 프롬프트는 품목 목록과 키트 레시피(예: "키트1번" → 컵라면, 샴푸리필, 양갱)로 만듭니다. 결과는 로봇에 넘기기 전에 검사해서, 지원하지 않는 품목이나 잘못된 수량, JSON이 아닌 응답은 거부합니다. 품목 목록은 `kit_vision`의 클래스 파일을 그대로 읽어서 음성과 비전의 품목 이름이 항상 같게 했습니다.
- **서비스 인터페이스.** `/get_command` 서비스로 제공합니다. OpenAI 크레딧 소진과 요청 한도 초과는 대응 방법이 달라서(충전 vs 재시도) 서로 다른 오류로 알립니다.

### 3. `kit_vision` — 객체 탐지에서 3D 위치까지
- **카메라 입력.** RealSense 컬러, 정렬된 depth, 카메라 정보를 구독하되 최신 프레임만 유지하고, 컬러와 depth의 시각 차이가 큰 쌍은 버립니다.
- **추론 루프.** YOLO segmentation 모델을 별도 스레드에서 약 3 Hz로 돌립니다. PyTorch가 CPU 스레드를 10~16개씩 잡아 RealSense USB 드라이버가 밀리는 문제가 있어서, 스레드 수를 제한했습니다.
- **3D 위치 계산.** 품목마다 **segmentation 폴리곤 안 유효 depth의 중앙값**을 써서 중심 픽셀 하나보다 노이즈에 강하게 했고, 카메라 내부 파라미터로 카메라 좌표로 변환합니다. 클래스, 점수, 위치, 마스크와 디버그 영상을 함께 발행합니다.
- **초기 위치 추정.** 카메라 좌표를 Hand–Eye 보정 결과로 로봇 베이스 좌표로 변환했고, 오래된 검출 결과로 로봇이 움직이지 않도록 timestamp 기반 최신성 검사를 추가했습니다.
- **컨테이너.** GPU 추론을 Docker로 패키징했습니다.

### 4. MoveIt 2용 OctoMap 장애물 환경
- **포인트 클라우드 필터링.** RealSense 포인트 클라우드 → 잘못된 점 제거 → 0.28 m보다 가까운 점 제거 → 로봇 베이스 좌표로 변환 → 1 cm voxel → 주변 27칸 중 4칸 이상 차 있는 voxel만 유지. 떨어져 있는 depth 노이즈는 없애고, 얇은 상자 벽과 모서리는 남깁니다.
- **정적 지도.** 관찰 자세에서 3초간 스캔한 뒤 지도를 고정해 작업 사이에 재사용합니다. 작업 중에 경로 계획이 느려지거나 바뀌지 않게 하기 위해서이고, 실행할 때마다 지도를 초기화합니다.
- **반복 조정 끝에 범위 축소.** 실시간 OctoMap은 로봇 팔, 그리퍼, 트레이 표면 노이즈까지 장애물로 잡아 경로 계획이 자주 실패했습니다. voxel 크기, RealSense 필터, 대상 물체 마스킹을 16번에 걸쳐 조정했고, 최종적으로 검사 영역의 정적 지도로 범위를 좁혔습니다.
- **충돌 허용 설정.** 그리퍼와 손목 링크는 OctoMap과 닿아도 되게 했습니다. 그렇지 않으면 그리퍼 자체에 찍힌 점 때문에 모든 경로 계획이 막힙니다. 이 설정은 *현재* 충돌 허용 행렬에 합쳐서 보냅니다. 일부만 보내면 행렬 전체가 바뀌어 로봇의 자기 충돌 규칙이 조용히 사라지기 때문입니다.

### 5. 전체 시스템 통합
- 음성 → 비전 → 위치 추정 → 컨트롤러 → 모션 → 최종 검사 → DB로 이어지는 End-to-End 흐름을 연결하고, 팀과 함께 실제 로봇에서 전체 시스템을 실행했습니다.

## 결과

### 1차 End-to-End 평가 (2026.09.08 · v0.1.0)
실제 로봇으로 22회 수행했습니다. Pick 영역에 품목 8~9개를 무작위로 놓고, 키트 트레이에 상자를 장애물로 두었습니다. MongoDB 실행 기록으로 분석했으며, 그리퍼의 자체 성공 판정이 부정확해 파지 결과는 영상을 보고 직접 라벨링했습니다.

| 지표 | 결과 |
|---|---:|
| **명령 키워드 인식** (음성) | **20/22 (90.9%)** |
| **유효한 JSON 명령 생성** (LLM + 검증) | **22/22 (100%)** |
| 품목 작업 성공 | 84/116 (72.4%) |
| 구성 완료 (실제로 키트에 담긴 품목) | 78/112 (69.6%) |
| 키트 완성 | 3/22 (13.6%) |
| **End-to-End 성공** (키트 완성 *및* 최종 검사 PASS) | **0/22 (0%)** |
| 최대 연속 가동 | 1시간 13분 |

- **음성 쪽(제 `kit_voice`)**: 인식된 명령은 모두 유효한 JSON이 됐습니다. 놓친 2건은 키트 이름을 잘못 알아들은 음성 인식 오류("응급기트", "시사 킬투")였고, 해석 오류는 없었습니다.
- **실패 지점**: 병목은 명령 인식이 아니라 파지와 최종 검사였습니다. 품목별 파지 성공률 편차가 컸는데, 햄 86.7%, 샴푸리필·숟가락 85.7%인 반면 컵라면 53.3%, 마스크 16.7%였습니다. 2D 마스크와 depth 기반 파지가 모든 형상에 맞지 않는다는 것을 확인했습니다.

### 평가 이후 개선 (v0.2.0)
- **모션:** 고정 Cartesian 경로와 관절 목표가 반복적으로 실패해, Pick과 관찰 이동을 충돌 검사가 포함된 **MoveIt 2 Pose Goal** 방식으로 바꿨습니다.
- **OctoMap:** 위에서 설명한 정적 지도로 검사 영역에 적용했습니다. Pick·관찰 영역 적용은 포인트 클라우드 노이즈가 계속 가짜 장애물을 만들어 최종 적용에서 제외했습니다.
- **파지:** 컵라면에 6자유도 파지 파이프라인(FoundationPose + GraspGenX)을 붙였습니다. 후보 최대 5개, 재관찰 최대 3회입니다.

> **한계:** 계획했던 2차 평가(20회)를 수행하지 못해서, 1차 평가 대비 개선 효과는 주장하지 않습니다.
